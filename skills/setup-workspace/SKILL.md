# AI 项目开局与续接

> Skill 版本：v2.0.0

把一件事正式开成一个 AI 可以跨会话持续推进的项目。“项目”可以是产品、研究、写作、运营、学习、活动或软件开发，不限于代码仓库。

完成标准不是“建了几个文件夹”，而是：AI 和用户已经对项目目标、当前阶段、下一份交付物和最小下一步形成一致理解，后续 AI 只读项目文件也能续接。

## 责任边界

- 建立或修复项目上下文、当前状态、材料入口、产出位置和下一步。
- 只在有可写本地目录的 AI 环境中执行。
- 不生成 Agent 库、Skill 清单、项目台账、软链体系、完整知识库或使用教程。
- 不把项目初始化扩大成领域交付、技术选型或代码脚手架；用户同时要求开始实际任务时再继续。
- 不删除、移动、重命名或覆盖已有文件，除非用户明确授权。

## 执行流程

### 1. 判断开局模式

| 模式 | 判定 | 处理重点 |
|---|---|---|
| 空白开局 | 只有想法或目标，没有项目目录 | 明确目标和当前完成标准，创建最小骨架 |
| 带材料开局 | 已有文档、截图、代码、聊天记录或链接 | 先读材料，从证据形成项目理解，不要求用户重述 |
| 接管旧项目 | 已有目录和部分产物，但状态散乱或已中断 | 盘点现状，保留原结构，补齐项目入口和下一步 |

多种模式同时存在时，优先按“接管旧项目”处理，因为保护现有资产比重新创建更重要。

### 2. 创建前先读现场

1. 使用用户明确给出的路径；用户说“就在这里”时使用当前工作目录。无法确定目标目录时先询问，不自行选一个位置。
2. 查看目标目录顶层结构，识别已有材料、产物、代码库和命名习惯。不无边界递归读取大目录。
3. 优先读取已有的 `PROJECT.md`、`AGENTS.md`、`CLAUDE.md`、项目说明、当前计划和最新阶段产物。
4. 如果现有目录已有 `sources/`、`docs/`、`deliverables/`、`dist/` 或其他等价结构，优先复用，不为了符合模板创建重复目录。
5. 发现已有协作规则时先遵守。需要补充时只增加必要项，不重写整份文件。

### 3. 形成项目理解

先根据已有信息输出简短理解草案，再只补会改变项目结构或当前交付物的缺口。

优先明确：

- 项目最终想改变什么；
- 当前阶段做到什么程度算完成；
- 已经有哪些可用材料和历史结论；
- 本次范围和明确不做的内容；
- 当前交付物和最小下一步。

每轮最多追问 3 个问题。给出基于现有信息的选项、示例或默认判断，避免把用户丢回空白框。不必询问岗位，除非它会改变项目交付物或权限边界。

### 4. 判断当前阶段和下一份交付物

使用轻量通用链路帮助判断，不强制用户学习这套名称：

```text
明确问题 → 整理输入 → 形成产物 → 检查验证 → 迭代交付
```

- 只设置一个当前阶段和一份主交付物。
- 交付物应是能被使用、确认、审查或验证的具体结果，不是“继续研究”之类模糊动作。
- 当前信息不足以判断后续方案时，将下一份交付物设为“当前理解 + 待确认清单”，不制造假计划。

### 5. 建立或补全项目骨架

新项目默认使用：

```text
<project>/
├── PROJECT.md
├── AGENTS.md 或 CLAUDE.md
├── inputs/
└── outputs/
```

这是默认值，不是强制模板。现有项目已有等价结构时保留原样并在 `PROJECT.md` 中记录实际路径。

1. 读取 `references/project-template.md`，创建或补全 `PROJECT.md`。填入真实信息，不保留模板说明和无意义空章节。
2. 新项目创建 `inputs/` 与 `outputs/`。用户的现有材料默认保留在原位，只在 `PROJECT.md` 中建立索引；未授权时不移动或复制。
3. 读取 `references/adapter-templates.md`，按当前运行环境选择 `AGENTS.md` 或 `CLAUDE.md`。需要同时支持多种 AI 时可同时创建，但两者都只做薄适配层。
4. 无法判断哪个协作文件会被当前环境自动读取时，先创建 `PROJECT.md`；只在自动读取确实重要时询问用户所用工具。
5. 软件项目的代码、测试和构建产物继续使用仓库原有结构，不强行放入 `outputs/`。

### 6. 让项目真正开始

初始化完成后，给出一张简短开局卡：

- 项目目标；
- 当前阶段；
- 当前主交付物；
- 已有材料入口；
- 最小下一步。

用户同时要求“建项目并开始做”时，继续执行第一个真实动作。用户只要求初始化时，给出一个针对当前项目的具体下一步，不再输出两个泛化示例提示词。

### 7. 续接时维护最小状态

已有 `PROJECT.md` 时将请求视为续接或升级，不重新初始化。每完成一个里程碑，只更新：

- 已完成的关键结果及其路径；
- 当前阶段和主交付物；
- 新的已确认或待确认项；
- 当前阻塞；
- 最小下一步。

不把 `PROJECT.md` 变成每次对话的日志。只保留会改变后续理解和行动的最新状态。

## 交付检查

- 是否先读取现有目录和项目规则，没有盲目创建或覆盖；
- 是否以项目目标和当前交付物为中心，而不是生成泛化个人画像；
- `PROJECT.md` 是否只包含真实信息，没有残留占位符或假完整；
- 是否只有一个当前阶段、一份主交付物和一个最小下一步；
- 是否记录了已有材料和正式产出的实际路径；
- AI 协作文件是否只做薄适配层，没有复制整份项目上下文；
- 是否克制住了范围，没有生成 Agent 库、Skill 台账、教程或重装目录体系；
- 收尾是否说清当前阶段、交付物和具体下一步。

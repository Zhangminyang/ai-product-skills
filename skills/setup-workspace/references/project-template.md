# PROJECT.md 生成规则

`PROJECT.md` 是项目当前事实和推进状态的工具无关入口。它应让一个没参与过上次对话的 AI，在读取后知道这是什么项目、现在做到哪里、下一步应做什么。

## 填写原则

- 用用户和现有材料中的具体语言，避免“提升效率”“赋能业务”之类空话。
- 区分项目最终目标和当前阶段完成标准。
- 材料存在不代表内容仍然有效；对历史口径、冲突和时效性保留说明。
- 只写已知内容。会阻碍当前交付的缺口写为 `[待确认]`；不重要的空章节直接删除。
- 使用实际相对路径或绝对路径索引材料和产物，不写“见相关文件”。
- 只保留一个当前阶段、一份主交付物和一个最小下一步。
- 已有 `PROJECT.md` 时就地补全或更新，不创建第二份项目说明。

## 默认骨架

根据项目复杂度删减章节，不要把下方占位符原样写入交付文件。

```markdown
# [项目名称]

> 最后更新：[当前日期]

## 项目目标

[这个项目最终要产生什么可观察结果，为谁解决什么事]

## 当前阶段完成标准

[做到什么程度，当前阶段就可以结束或进入下一阶段]

## 背景与已有材料

- `[路径或链接]` — [内容、用途、有效性或需注意的口径]

## 当前范围

**本次处理**

- [内容]

**暂不处理**

- [内容及原因]

## 当前状态

- 当前阶段：[明确问题 / 整理输入 / 形成产物 / 检查验证 / 迭代交付]
- 当前主交付物：[具体产物及计划路径]
- 已完成：[最近会改变后续理解的结果]
- 当前阻塞：[没有则写“无”]

## 已确认与待确认

**已确认**

- [会影响后续范围或产物的有效结论]

**待确认**

- [问题] — [需要谁或什么证据确认，影响什么]

## 协作边界

- 需要用户决定：[范围、优先级、风格、业务规则或其他关键决策]
- AI 可以直接处理：[整理、起草、检查、实现或其他已授权工作]

## 项目路径

- 输入材料：`[实际路径]`
- 正式产出：`[实际路径]`

## 下一步

[一个可以立即开始、完成后会明显推进当前交付物的动作]
```

## 续接更新

里程碑完成后，优先修改“当前状态”“已确认与待确认”“下一步”和更新日期。不追加完整对话日志；需要保留过程记录时使用项目现有的日志、版本记录或决策文件。

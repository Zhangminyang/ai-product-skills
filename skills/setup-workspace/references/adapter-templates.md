# AI 环境适配规则

`PROJECT.md` 保存项目事实和当前状态；`AGENTS.md` 或 `CLAUDE.md` 只负责让对应 AI 在进入项目时自动找到这些内容。不要在多份文件中复制项目背景、范围和当前状态。

## 选择规则

| 环境 | 适配文件 |
|---|---|
| Codex 或明确读取 AGENTS.md 的工具 | `AGENTS.md` |
| Claude Code、Cowork 或明确读取 CLAUDE.md 的工具 | `CLAUDE.md` |
| 项目需同时为两者服务 | 同时创建，保持内容简短一致 |
| 无法确定工具 | 先只创建 `PROJECT.md`，确实需要自动读取时再确认 |

## 新建 AGENTS.md

```markdown
# 项目协作规则

- 开始工作前先读取 `PROJECT.md`，以其中的当前目标、范围、状态和下一步为准。
- 优先使用 `PROJECT.md` 索引的现有材料；未确认信息不得编造。
- 正式产出使用 `PROJECT.md` 记录的产出路径；现有项目结构优先于默认目录。
- 不自行扩大当前范围；需要用户决定的事项明确标为待确认。
- 完成里程碑后，更新 `PROJECT.md` 的当前状态、关键结论、阻塞和最小下一步。
```

## 已有协作文件

1. 完整读取已有文件和上层目录的适用规则。
2. 判断是否已经覆盖“读项目入口、尊重范围、使用真实材料、记录产出、维护状态”五项核心规则。
3. 已经等价覆盖时不做任何修改。
4. 缺少时只追加一个简短的“项目续接”小节，不重写、重排或精简用户已有规则。
5. 新增内容与现有规则冲突时停止修改，说明冲突并请用户决定。

### 最小追加段

```markdown
## 项目续接

- 开始当前项目工作前读取 `PROJECT.md`。
- 里程碑完成后，只回写会改变后续工作的当前状态、阻塞和下一步。
```

## 边界

- 不在项目适配文件中重复全局个人偏好；由对应 AI 工具的全局配置继承。
- 不把 `PROJECT.md` 全文复制进适配文件。
- 不写入当前环境不存在的 Skill、Agent 或工具名称。
- 不修改上层目录或全局配置，除非用户明确要求。
